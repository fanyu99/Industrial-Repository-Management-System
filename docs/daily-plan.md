### Day 17：入库真实链路测试与异常注入（已完成）

**目标：** 验证入库确认事务在真实 MySQL 链路中的回滚、幂等和错误映射行为。

**知识点：**

- 事务测试的观察点：业务表状态、库存余额、库存流水、审计日志必须一起核对。
- 幂等测试与重复提交测试的区别：重复提交应被状态守卫拦截，不能重复产生库存变化。
- 异常注入测试的边界：优先构造真实业务可发生的失败场景，不为了覆盖率硬造不合理路径。
- 错误映射测试：区分 `AffectedRowsConditionNotMet`、唯一键冲突、外键约束失败和普通 SQL 执行失败。

**重点任务：**

- 整理真实 MySQL 验证用例，固定正常确认、多明细确认、重复确认三类已通过场景。
- 补充至少一个事务回滚验证场景，证明失败时订单、库存余额、库存流水和审计日志不会部分提交。
- 注入或模拟重复确认、非法状态确认、关键外键失败、唯一键冲突等异常路径。
- 验证业务错误、数据库错误和事务回滚结果的映射。
- 对比确认前后的订单、库存余额、库存流水和审计日志。
- 补充 Repository 与 Service 的边界测试，确保 Service 不承担事务拼装职责。

**验收标准：**

- 事务失败注入测试能够证明全局回滚。
- 重复请求具备幂等结果，不产生重复库存变化。
- 真实 MySQL 链路测试通过，并留下可重复执行的验证方式。

**完成状态：** 已完成。真实链路测试已验证正常确认、多明细确认、重复确认、事务失败回滚与相关错误映射；重复确认不会重复增加库存，失败路径不会留下订单、余额、流水和审计日志的部分提交结果。
